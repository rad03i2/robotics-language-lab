# Contributing / المساهمة

Thank you for improving Robotics Language Lab. Keep contributions small, runnable, and easy to inspect.

## English
- Open an issue for substantial behavioral or structural changes before investing in a large patch.
- Keep each example focused on one robotics concept and document its assumptions.
- Prefer standard-library solutions when they keep an example clearer.
- Never commit credentials, device secrets, private camera URLs, generated binaries, build output, or personal telemetry.
- For hardware examples, document expected board/pins/voltage assumptions and use conservative defaults.
- Add or update tests when changing reusable logic.
- Run `python -m unittest discover -s tests -v` and the relevant compiler/toolchain before submitting.
- Keep documentation truthful: do not claim hardware, ROS, performance, or safety validation that was not performed.

## العربية
شكرًا للمساهمة في تطوير المشروع. اجعل الإضافات صغيرة وقابلة للتشغيل وسهلة القراءة.

- ناقش التغييرات الكبيرة عبر Issue قبل تنفيذ تعديل واسع.
- اجعل كل مثال يركز على مفهوم روبوتات واحد مع توثيق افتراضاته.
- لا ترفع كلمات مرور أو بيانات أجهزة أو روابط كاميرات خاصة أو ملفات بناء مولدة أو telemetry شخصية.
- في أمثلة العتاد، وثق نوع اللوحة والأرجل والجهد المتوقع واستخدم قيمًا محافظة.
- أضف أو حدّث الاختبارات عند تغيير منطق قابل لإعادة الاستخدام.
- شغّل الاختبارات والأداة/المترجم المناسب قبل إرسال التغيير.
- لا تدّعِ اختبار عتاد أو ROS أو أداء أو سلامة لم يتم التحقق منها فعليًا.
